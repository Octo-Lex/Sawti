# M2 Plan — Live microphone → existing Sawti graph

**Status: APPROVED, READY FOR IMPLEMENTATION** (reviewer-authored 2026-08-21;
frozen as the M2 contract per Task 0). Branch: `feat/m2-live-mic`.

The architecture is deliberately narrow. `AudioSource` already requires only
timestamped `AudioFrame`s, and `FileSource` establishes the production audio
contract as contiguous mono `float32` at 16 kHz. The design spec explicitly
defines M2 as **live mic → chunked target-language text**, names
`MicSource (sounddevice)` as the deployment edge, and keeps token-level
streaming for M3.

## Locked M2 architecture

```text
PortAudio / sounddevice callback
           │
           │ non-blocking copy only
           ▼
     bounded audio queue
           │
           ▼
        MicSource
           │ AudioFrame(float32 mono, 16 kHz, session timestamp)
           ▼
      EXISTING Pipeline
           │
 RealSegmenter → M4T → gate/fallback → postprocess
           ▼
  terminal OutputSegments
```

The **core graph does not change**. `Pipeline.run()` remains its existing
sequential generator. Capture continues in the sound-device callback while
inference is running; buffered audio is consumed when the pipeline requests
the next frames.

Do **not** introduce asyncio, worker inference threads, a second pipeline,
token streaming, LID-based segmentation, or a new engine mode in M2. Those
are separate concerns.

For capture, use `sounddevice.InputStream` (current sounddevice docs at
0.5.5 explicitly recommend `InputStream` for block-wise NumPy capture). Its
callback runs under real-time constraints and must not do blocking or
unpredictable work. The callback does nothing beyond checking status,
copying the incoming block, and a **non-blocking** enqueue — consistent
with sounddevice's own recording examples, which copy callback data into a
queue for work outside the callback.

## M2 contract (frozen — Task 0)

- M2 is **capture-only integration**: core pipeline semantics are frozen.
- Session target language remains fixed for the whole session.
- Capture output is mono `float32` at 16 kHz.
- **No silent audio loss** — ever.
- Token streaming remains M3.
- Arbitrary-device streaming resampling is initially out of scope.
- **Release rule:** if a microphone cannot open mono float32 at 16 kHz,
  fail BEFORE the session rather than silently reinterpreting another rate.

## Implementation sequence

### Task 1 — Mic dependency without weakening portable installs

Optional extra, not on every CI/default install:

```toml
[project.optional-dependencies]
mic = ["sounddevice>=0.5.5"]
```

Operator install: `uv sync --extra mic`. Imports stay lazy so `import
sawti`, unit tests, and non-mic CLI commands work without the extra.
Actionable failure (`MicUnavailableError`) when the extra or the PortAudio
backend is unavailable. **Gate: default portable CI must remain green.**

### Task 2 — `sawti/mic_source.py` (flat package; no `sources/` reorg)

`MicSource` implements the existing `AudioSource` protocol. Defaults:

```python
TARGET_SR = 16000
CHANNELS = 1
DTYPE = "float32"
BLOCK_MS = 100
QUEUE_SECONDS = 30
```

Before opening the stream, run the backend's input-setting validation for
the selected device at 16 kHz/mono/float32. Device may be `None`, numeric
ID, or name substring.

The callback uses a bounded `queue.Queue`, copies the mono block, and calls
`put_nowait()`. A full queue is **fatal**, not a reason to discard the
oldest/newest block. Likewise an input-overflow status is fatal. The next
consumer iteration raises a specific `MicOverflowError`/`MicCaptureError`,
terminating the session visibly.

Authoritative `AudioFrame.timestamp_s` comes from a cumulative sample
cursor: `timestamp = samples_emitted / 16000` — NOT callback wall-clock
arrival time. Deterministic, jitter-free session timestamps as long as
capture continuity holds; any loss fails the session instead of falsifying
the timeline.

`close()`/`stop()` are idempotent; stream cleanup guaranteed in `finally`.
**Gate: no changes to pipeline.py, segmenter_silero.py, fallback, gate, or
model code.**

### Task 3 — Hermetic microphone-source tests

`tests/test_mic_source.py` with an injected fake sounddevice/backend; no
microphone and no `sounddevice` import required. Pin at least: preflight
called with 16 kHz/mono/float32; emitted arrays are contiguous 1-D
`np.float32`; cumulative timestamps exact and monotonic; callback order
preserved; variable final block size preserves timestamp arithmetic; queue
saturation fails loudly rather than dropping; backend input-overflow status
fails loudly; `close()` idempotent; stream closes on generator
exit/exception; unavailable optional dependency gives an actionable error;
module import hermetic on CPU-only CI. Plus one source-contract regression
using a known synthetic waveform proving the callback/queue boundary does
not alter samples.

### Task 4 — New CLI edge (do not overload M1 semantics)

`sawti listen --target eng` — NOT a change to `sawti transcribe` (whose
no-file path remains the stub demo). Options:

```text
--target eng|ara|fra
--device <id-or-name>
--list-devices
--config-path config/default.yaml
```

`listen` constructs the SAME `_real_pipeline(config)` as M1 and substitutes
only `MicSource` for `FileSource`. `Ctrl+C` = normal teardown + clean exit,
no traceback. Output keeps the existing `[start-end] text` interface.
`--list-devices` must not load M4T/Silero/Whisper. No `--engine sawti-sa`
(primary Saudi mode = separate review); no change to `provider="sa"`.

### Task 5 — CLI and graph-contract tests

Extend `tests/test_cli.py` with an injected finite fake `MicSource` and
fake/stub pipeline: `listen` forwards target; selected device reaches
`MicSource`; list-devices exits without building the ML graph; mic errors
become clean CLI failures; Ctrl-C/finite-source exit closes capture;
`transcribe`/`eval` unchanged. Plus one integration-style hermetic replay
test: known waveform blocks through the MicSource fake callback → existing
segmenter/pipeline stubs, verifying order/timestamps survive the live edge
(proof M2 uses the M1 graph, not a parallel implementation).

### Task 6 — Capture observability

`MicSource` exposes a small read-only stats snapshot (not a metrics
subsystem): captured samples/seconds, emitted samples/seconds, current +
high-water queue depth, callback status/overflow count, queue-overflow
count, selected device, sample rate, block size. On termination `listen`
prints a concise summary to **stderr** (transcript stdout stays
machine-friendly). Rationale: RTF < 1.0 is required for M2/M3 — a
downstream model falling behind must become observable before the queue
reaches its hard failure boundary.

### Task 7 — Operator hardware smoke and M2 acceptance

After hermetic CI green:

```bash
uv sync --extra mic
uv run sawti listen --list-devices
uv run sawti listen --device "<chosen mic>" --target eng
```

Short capture-only device check first, then a real production-path
conversational session on the existing M4T graph.

**Release PASS requires:** zero PortAudio input-overflow events; zero
queue-overflow events; no silently missing samples; monotonic
source/output timestamps; multiple non-empty output segments from real
speech; clean Ctrl-C shutdown; no ML model load during device listing;
the capture queue must demonstrably catch up during several-second
silence rather than grow indefinitely. Record queue high-water and
per-chunk/output latency as the initial M2 latency baseline. A failure
because downstream inference cannot catch up is an **M2 performance
failure**, not permission to drop input.

At least one several-minute code-switched session for the release smoke.
No new translation-quality benchmark: M2 validates the **live transport
boundary**; M1 owns pipeline quality.

### Task 8 — PR and merge gate

README usage + OS microphone prerequisites (optional `mic` install). M2 PR
with no SA-training changes; required `test` must pass under the enforced
branch protection. Operator evidence separate from CI evidence: device/OS,
selected PortAudio device, session duration, capture status counts, queue
high-water, output sample, clean-shutdown result. Squash merge only after
the real-device smoke passes.

## Explicit non-goals

Continuous streaming resampling from arbitrary native device rates; true
incremental/token decoding; concurrent model workers; language-switch
segmentation; primary Saudi Whisper routing; frontend/UI; WebSockets;
server transport. M2 = chunked live input; M3 = near-real-time streaming.

If 16 kHz input preflight proves materially incompatible with the actual
target microphone during Task 7, **stop at that gate**. The corrective
scope is a dedicated stateful capture-resampling seam; never per-block
resampling inside the callback or independent per-block resampling
(discontinuities, false timestamps).
